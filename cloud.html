PART 1: CORE & FOUNDATIONAL QUESTIONS

Cloud & DevOps Fundamentals Basic • Developer

Core cloud computing models, virtualization, CI/CD automation, and cloud networking basics.

1. IaaS vs PaaS vs SaaS: Key differences and shared responsibility model

IaaS (Infrastructure as a Service): Cloud provider manages hardware and virtualization; customer manages OS, runtime, and app (e.g. AWS EC2, GCP GCE). PaaS (Platform as a Service): Provider manages OS and runtime; customer manages app code (e.g. Cloud Run, Elastic Beanstalk). SaaS (Software as a Service): Fully managed end-user application (e.g. Gmail, Salesforce).

2. Virtual Machines (Hypervisors) vs Containers

Virtual Machines virtualize the hardware layer via a Hypervisor (Type 1 or Type 2), running a complete guest OS with separate kernel per VM. Containers share the host Linux kernel, isolating user space via namespaces and cgroups, booting in milliseconds with negligible overhead.

PART 2: ADVANCED & 2026 INTERVIEW SPECS

Advanced Cloud Architecture & Enterprise DevOps Senior • Tech Lead • 2026

Multi-region active-active disaster recovery, FinOps cost governance, Karpenter autoscaling, and Chaos Engineering.

High Availability • Disaster Recovery

1. Multi-Region Active-Active Architecture: RPO, RTO, and Data Synchronization.

  • RPO (Recovery Point Objective): Maximum acceptable data loss duration during an outage.
  • RTO (Recovery Time Objective): Maximum acceptable downtime duration to restore service.
  • Active-Active Architecture: Traffic routed to both regions via Anycast DNS (Route 53 latency-based routing or Cloudflare). Databases use multi-region active-active replication (Aurora Global Database or Cloud Spanner) with automatic conflict resolution.
Cloud Financial Engineering • FinOps

2. FinOps: Cloud Cost Optimization and Unit Economics.

As a Tech Lead, managing cloud expenditure requires: 1) Utilizing Spot Instances / Preemptible VMs for stateless workloads; 2) Right-sizing container CPU/memory requests based on Prometheus P95 metrics; 3) Storage lifecycle policies transitioning S3/GCS to Glacier/Archive; 4) Purchasing Savings Plans for baseline continuous compute.
