Kafka Fundamentals

Q1: Explain Kafka Architecture (Brokers, Topics, Partitions, Replicas)

Apache Kafka is a distributed event store and stream-processing platform. Key primitives:

  • Topic: Logical category or stream to which records are published.
  • Partition: An ordered, immutable commit log. Each partition provides strict ordering via 64-bit integer offset.
  • Broker: Stateless or KRaft-managed server node hosting partition replicas.
  • Leader & ISR (In-Sync Replicas): Each partition has one leader handling all reads/writes and multiple follower replicas replicating data.
Kafka Fundamentals

Q2: How does Consumer Group Rebalancing work and what are the triggers?

A consumer group distributes topic partitions among members such that each partition is processed by exactly one consumer within the group.

Triggers for Rebalance:

  1. New consumer joins the group.
  2. Consumer crashes or misses heartbeat (session.timeout.ms).
  3. Consumer takes too long processing records before invoking poll (max.poll.interval.ms).
  4. New partitions added to the topic.

Advanced Distributed Streaming (2026)

Advance Q1 (2026): ZooKeeper-less Kafka (KRaft Mode) & Metadata Quorum

In modern Kafka, Apache ZooKeeper has been completely replaced by KRaft (Kafka Raft Metadata mode):

  • Consensus Quorum: A subset of brokers are designated as KRaft Controllers running Raft consensus directly on an internal metadata topic (@metadata).
  • Instant Cluster Recovery: Metadata replication happens in milliseconds; zero external ZK connection bottlenecks when managing 1,000,000+ partitions.
  • Simplified Security & Operations: Single binary, unified TLS/SASL security perimeter.

Advance Q2 (2026): Exactly-Once Semantics (EOS) with Transactional Producer & Idempotence

How Kafka achieves end-to-end exactly-once delivery across consume-process-produce loops:

// Production-ready Idempotent & Transactional Producer configuration
Properties props = new Properties();
props.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, "kafka-broker:9092");
props.put(ProducerConfig.ENABLE_IDEMPOTENCE_CONFIG, "true"); // enforces acks=all, retries=MAX, max.in.flight.requests=5
props.put(ProducerConfig.TRANSACTIONAL_ID_CONFIG, "order-proc-tx-1");

Producer producer = new KafkaProducer<>(props);
producer.initTransactions();

try {
    producer.beginTransaction();
    producer.send(new ProducerRecord<>("orders-processed", orderId, payload));
    producer.sendOffsetsToTransaction(consumerOffsets, consumerGroupId);
    producer.commitTransaction();
} catch (ProducerFencedException | OutOfOrderSequenceException e) {
    producer.close();
} catch (KafkaException e) {
    producer.abortTransaction();
}
