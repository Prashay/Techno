JUnit 5 & Mockito Core

Q1: Key differences between JUnit 4 and JUnit 5 (Jupiter)

JUnit 5 is composed of three sub-projects: JUnit Platform (engine execution), JUnit Jupiter (programming model), and JUnit Vintage (backward compatibility).

FeatureJUnit 4JUnit 5 (Jupiter)
Lifecycle@Before, @After, @BeforeClass@BeforeEach, @AfterEach, @BeforeAll
Extensions@RunWith, @Rule, @ClassRuleUnified @ExtendWith(MockitoExtension.class)
AssertionsAssert.assertEqualsAssertions.assertAll(), assertThrows()
Tagging@Category@Tag("integration"), @Tag("smoke")
JUnit 5 & Mockito Core

Q2: Difference between @Mock, @Spy, and @InjectMocks in Mockito

@Mock: Creates a dummy stub implementation where all non-stubbed methods return default values (null, 0, false).

@Spy: Wraps a real object instance. Non-stubbed methods invoke the actual production code logic, while allowing specific methods to be mocked.

@InjectMocks: Automatically creates an instance of the class under test and injects mocks and spies created via @Mock or @Spy into its constructor or fields.

Advance Q1 (2026): Integration Testing with Testcontainers & Spring Boot @ServiceConnection

In 2026, embedded databases (H2, Embedded Kafka) are obsolete due to SQL dialect mismatches. Modern enterprise tests use Testcontainers with dynamic service connections.

import org.junit.jupiter.api.Test;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.testcontainers.service.connection.ServiceConnection;
import org.testcontainers.containers.PostgreSQLContainer;
import org.testcontainers.junit.jupiter.Container;
import org.testcontainers.junit.jupiter.Testcontainers;

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@Testcontainers
class OrderServiceIntegrationTest {

    @Container
    @ServiceConnection // Automatically wires spring.datasource.url/username/password
    static PostgreSQLContainer postgres = new PostgreSQLContainer<>("postgres:16-alpine");

    @Test
    void shouldPersistOrderWithinRealPostgres() {
        // Real PostgreSQL execution verifying dialect, constraints, and JSONB fields
    }
}
