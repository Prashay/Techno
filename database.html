PART 1: CORE & FOUNDATIONAL QUESTIONS

Database Systems Fundamentals Basic • Developer

Core relational principles, NoSQL models, ACID transactions, and indexing basics.

1. Relational (SQL) vs NoSQL: Architectural Decision Matrix

Relational (PostgreSQL/MySQL): Best for structured data, multi-table transactions, strict foreign-key integrity, and financial ledgers.
NoSQL (MongoDB/DynamoDB): Best for flexible unstructured document schemas, horizontal partition scaling, high-frequency IoT streaming, and rapid schema evolution.

2. The ACID Properties in Database Transactions

  • Atomicity: All operations in a transaction succeed, or the entire transaction rolls back.
  • Consistency: The database transitions from one valid state to another, upholding all constraints.
  • Isolation: Concurrent transactions execute without interfering with each other (Read Committed, Repeatable Read, Serializable).
  • Durability: Once committed, updates persist permanently even during sudden power failure (via Write-Ahead Log).
PART 2: ADVANCED & 2026 INTERVIEW SPECS

Advanced Database Architecture & Distributed Systems Senior • Tech Lead • 2026

Sharding, Read Replicas, CAP/PACELC theorems, Connection Pooling, and Zero-Downtime Schema Migrations.

Scalability • High Availability

1. Database Sharding vs Read Replication: Trade-offs & Pitfalls.

  • Read Replication: One master node handles writes and streams logs to multiple read replicas. Pitfall: Replication Lag causes dirty reads (user saves profile, refreshes immediately, and sees old data). Solution: Route writes and reads-after-write to the primary node for 5 seconds.
  • Sharding: Horizontally partitions data rows across multiple independent database servers based on a shard key. Pitfall: Cross-shard transactions and cross-shard queries become slow and complex.
Distributed Systems • Theory

2. CAP Theorem vs PACELC Theorem in Modern Distributed Data Stores.

The CAP Theorem (Consistency, Availability, Partition Tolerance) only describes behavior during network partitions. The PACELC Theorem extends it to describe normal operating latency:

"If there is a Partition (P), trade off Availability (A) vs Consistency (C); Else (E), trade off Latency (L) vs Consistency (C)."

Examples: MongoDB is PC/EC (prefers consistency in both partition and normal states); DynamoDB is PA/EL (prefers availability and low latency over strict consistency).
