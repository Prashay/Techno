PART 1: CORE & FOUNDATIONAL QUESTIONS

SQL Fundamentals Basic • Developer

DDL vs DML, JOIN types, WHERE vs HAVING, and Window Functions.

1. DDL vs DML vs DQL vs DCL vs TCL commands

DDL (Data Definition): CREATE, ALTER, DROP, TRUNCATE.
DML (Data Manipulation): INSERT, UPDATE, DELETE.
DQL (Data Query): SELECT.
TCL (Transaction Control): COMMIT, ROLLBACK, SAVEPOINT.

2. Difference between WHERE and HAVING clause

WHERE filters individual rows before any grouping or aggregation takes place. HAVING filters grouped records after the GROUP BY aggregation has been computed.

3. SQL JOIN Types: INNER vs LEFT vs RIGHT vs FULL OUTER

INNER JOIN returns records with matching keys in both tables. LEFT JOIN returns all records from left table and matched records from right table. FULL OUTER JOIN returns all rows when there is a match in either table.

4. Window Functions: ROW_NUMBER() vs RANK() vs DENSE_RANK()

FunctionBehavior on Duplicate ValuesSequence Example
ROW_NUMBER()Assigns strictly sequential integer without ties1, 2, 3, 4, 5
RANK()Assigns identical rank to ties, skips subsequent rank1, 2, 2, 4, 5
DENSE_RANK()Assigns identical rank to ties, does NOT skip next rank1, 2, 2, 3, 4
PART 2: ADVANCED & 2026 INTERVIEW SPECS

Advanced SQL & Query Optimization (2026) Senior • Tech Lead • 2026

EXPLAIN execution plans, composite indexes, CTEs, and deadlock resolution.

Performance • Query Plans

1. Reading EXPLAIN and EXPLAIN ANALYZE: Sequential Scan vs Index Scan vs Bitmap Scan.

  • Seq Scan (Table Scan): Reads every database block sequentially on disk. Acceptable for small tables or when fetching >30% of rows.
  • Index Scan: Traverses the B-Tree index to find row pointers (TIDs) and fetches heap pages individually. Fast for high-selectivity queries (<5% rows).
  • Bitmap Index Scan: Scans the index to build an in-memory bitmap of pages containing matching rows, then visits heap pages in physical disk order, preventing random I/O thrashing.
Indexing • Leftmost Prefix Rule

2. Composite Indexing and the Leftmost Prefix Rule.

When creating a composite index on (tenant_id, status, created_at), the database can use the index for queries filtering on:

  • tenant_id (Yes)
  • tenant_id AND status (Yes)
  • tenant_id AND status AND created_at (Yes)
  • status AND created_at (NO! Violates leftmost prefix; triggers a full scan or loose index scan).
Recursion • CTE

3. Recursive Common Table Expressions (WITH RECURSIVE) for Hierarchies.

Querying organizational hierarchies (employee managers) or graph relationships without multiple nested self-joins:

WITH RECURSIVE OrgChart AS (
    SELECT emp_id, manager_id, 1 as level FROM employees WHERE manager_id IS NULL
    UNION ALL
    SELECT e.emp_id, e.manager_id, o.level + 1
    FROM employees e INNER JOIN OrgChart o ON e.manager_id = o.emp_id
)
SELECT * FROM OrgChart ORDER BY level;
