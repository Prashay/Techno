Architecture • Concurrency

1. How do Java 21+ Virtual Threads integrate with Spring Boot 3.2+ and embedded Tomcat? What are the critical production pitfalls?

In Spring Boot 3.2+, virtual threads (Project Loom) can be enabled globally with a single configuration property:

spring.threads.virtual.enabled=true

Under the Hood: Spring Boot automatically configures the embedded Tomcat protocol handler (or Jetty) to use Executors.newVirtualThreadPerTaskExecutor(). Instead of dedicating a heavyweight OS platform thread (typically ~1MB stack) per incoming HTTP connection, Tomcat dispatches each HTTP request on a lightweight Virtual Thread mounted on an underlying pool of Carrier Threads (ForkJoinPool worker threads equal to available CPU cores).

Critical Production Pitfalls:
  • Carrier Thread Pinning: When a virtual thread executes inside a synchronized block or calls native code (JNI) and blocks on I/O, it cannot unmount from its carrier thread. This pins the OS carrier thread, quickly starving the ForkJoinPool. Mitigation: Replace legacy synchronized blocks with java.util.concurrent.locks.ReentrantLock and monitor via -Djdk.tracePinnedThreads=full.
  • ThreadLocal Memory Leaks & Overhead: Spawning millions of virtual threads that each inherit large ThreadLocal maps causes massive heap inflation and GC overhead. Mitigation: Migrate to Scoped Values (JEP 446) in Java 21+.
  • Database Connection Pool Saturation: Virtual threads allow concurrency from 200 requests up to 50,000+ requests simultaneously, but JDBC connection pools (HikariCP) are still limited by database connections (e.g., 50-100 max connections). Virtual threads will queue waiting on HikariCP connections. Use bounded semaphores to prevent connection pool exhaustion.
Performance • Cloud-Native

2. Explain Spring Boot 3.x Ahead-Of-Time (AOT) engine and GraalVM Native Image: compilation lifecycle, benefits, and reflection/proxy limitations.

Spring Boot 3 introduced a first-class AOT (Ahead-of-Time) processing engine that translates dynamic runtime configurations into static, pre-computed code tailored for GraalVM Native Image compilation.

AOT Compilation Lifecycle:
  • Build-Time Inspection: At build time (using spring-boot-maven-plugin:process-aot), Spring analyzes @Configuration, @ComponentScan, and condition evaluation (@ConditionalOn...) upfront.
  • Code Generation: It generates optimized Java source code that registers bean definitions programmatically without classpath scanning or dynamic runtime reflection.
  • Native Compilation: GraalVM compiles the generated code and JDK classes directly into a standalone binary (machine code) using closed-world analysis.
Key Benefits & Trade-offs:
Capability Standard JIT (JVM) GraalVM Native Image (AOT)
Startup Time 1.5s - 5.0s < 50ms (Near instantaneous)
Memory Footprint (RSS) 350MB - 600MB 30MB - 70MB (Ideal for serverless / scale-to-zero)
Peak Throughput Higher (due to runtime C2 JIT optimization) Slightly lower peak throughput without PGO (Profile-Guided Optimization)
Dynamic Reflection & Proxies Full runtime support Requires explicit RuntimeHints or @RegisterReflectionForBinding
Spring 6 API • HTTP Clients

3. What is Spring 6's RestClient and how does it compare against RestTemplate, WebClient, and Spring Cloud OpenFeign?

Introduced in Spring Framework 6.1 / Spring Boot 3.2, RestClient is a modern, synchronous HTTP client that provides the fluent, expressive API style of WebClient while backed by standard blocking HTTP libraries without requiring reactive dependencies (Project Reactor).

RestClient client = RestClient.builder()
    .baseUrl("https://api.inventory.service")
    .defaultHeader("Accept", MediaType.APPLICATION_JSON_VALUE)
    .requestInterceptor(authInterceptor)
    .build();

ProductResponse product = client.get()
    .uri("/products/{id}", productId)
    .retrieve()
    .body(ProductResponse.class);
Architectural Comparison:
  • vs RestTemplate: RestTemplate is in maintenance mode. RestClient is its modern replacement with clean chaining, better error handlers, and support for declarative HTTP interfaces (@HttpExchange).
  • vs WebClient: WebClient is non-blocking and reactive (requires spring-boot-starter-webflux). For standard servlet-based architectures, RestClient + Virtual Threads achieves massive concurrency without reactive complexity.
  • vs OpenFeign: Spring 6 now offers native declarative HTTP interfaces: you annotate an interface with @GetExchange("/api/orders"), and Spring automatically generates an implementation backed by RestClient, eliminating external Feign dependencies.
Fault Tolerance • Production Resiliency

4. How do you implement production-grade Resiliency and Rate Limiting in Spring Boot using Resilience4j?

Resilience4j provides modular fault tolerance primitives integrated with Spring Boot Actuator and Micrometer:

  • Circuit Breaker: Monitors downstream failures across a sliding window (count-based e.g. 100 calls, or time-based e.g. 60 seconds). Transitions:
    CLOSED (normal) → failure rate > threshold (e.g. 50%) → OPEN (fast-fail, immediate fallback without calling downstream) → wait duration elapsed (e.g. 10s) → HALF_OPEN (test probe calls) → success recovers to CLOSED.
  • RateLimiter: Enforces token-bucket rate limits per client or per endpoint (e.g., 100 requests per 10 seconds), returning HTTP 429 Too Many Requests when exceeded.
  • Bulkhead: Limits concurrent calls to a downstream service using isolated semaphores or thread pools, ensuring a slow third-party service cannot exhaust all Tomcat worker threads.
@CircuitBreaker(name = "paymentGateway", fallbackMethod = "paymentFallback")
@RateLimiter(name = "paymentRateLimit")
public PaymentResult processPayment(PaymentRequest request) {
    return paymentClient.charge(request);
}

public PaymentResult paymentFallback(PaymentRequest request, Throwable ex) {
    log.warn("Payment service degraded, queueing transaction: {}", ex.getMessage());
    return PaymentResult.queued(request.getTransactionId());
}
Observability • OpenTelemetry

5. How does Spring Boot 3 Observability work with Micrometer, W3C TraceContext, and OpenTelemetry?

In Spring Boot 3, metrics, logs, and distributed tracing are unified under the Micrometer Observation API:

  • Unified Observation: Instead of writing separate code for metrics and distributed tracing, you wrap business operations in an Observation (or annotate methods with @Observed). Micrometer automatically records timers, counters, and spans concurrently.
  • W3C TraceContext Propagation: When an HTTP call is received, Spring extracts the W3C traceparent header (e.g., 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01). It injects the traceId and spanId into the logging MDC (Mapped Diagnostic Context) so every log line contains correlation IDs.
  • OTLP Exporters: Spring Boot can stream traces and metrics directly via OpenTelemetry Protocol (OTLP) to Prometheus, Grafana Tempo, Datadog, or Jaeger without requiring vendor-specific agents.
Distributed Systems • API Design

6. How do you design Idempotent REST APIs and Transactional Outbox consumers in Spring Boot?

For financial transactions, checkout, and inventory mutation, network retries can duplicate requests unless strict idempotency is engineered:

  • Idempotency-Key Header: Clients send a unique UUID in the Idempotency-Key header on POST/PUT requests. A Spring filter / interceptor checks Redis: 
    Boolean acquired = redisTemplate.opsForValue()
    .setIfAbsent("idemp:" + key, "IN_PROGRESS", Duration.ofMinutes(10));
if (!acquired) {
    return fetchCachedResponseOrReject(key);
}
  • Database Deduplication: Maintain an idempotency_keys table with a primary key constraint on (key, client_id) inside the local ACID transaction.
  • Transactional Outbox Pattern: Never commit to the database and call kafkaTemplate.send() in the same method (dual-write hazard). Write the business entity AND an event record into an outbox table in the same database transaction. Use Debezium (CDC) or a transactional poller to stream outbox events to Kafka with at-least-once guarantee.

Program 1: Production-Grade Global Exception Handler with ProblemDetail (RFC 7807)

Asked across Tier-1 tech interviews. Replaces legacy unstructured error maps with standard HTTP Problem Details.

import org.springframework.http.*;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.*;
import java.net.URI;
import java.time.Instant;
import java.util.*;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ProblemDetail handleResourceNotFound(ResourceNotFoundException ex) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, ex.getMessage());
        problem.setTitle("Resource Not Found");
        problem.setType(URI.create("https://api.technointerview.com/errors/not-found"));
        problem.setProperty("timestamp", Instant.now());
        return problem;
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ProblemDetail handleValidationErrors(MethodArgumentNotValidException ex) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(HttpStatus.BAD_REQUEST, "Validation failed for request payload");
        problem.setTitle("Invalid Request Content");
        
        Map errors = new HashMap<>();
        ex.getBindingResult().getFieldErrors().forEach(err -> 
            errors.put(err.getField(), err.getDefaultMessage()));
            
        problem.setProperty("fieldErrors", errors);
        problem.setProperty("timestamp", Instant.now());
        return problem;
    }
}

Program 2: Custom Validation Annotation (@ValidPhoneNumber) with ConstraintValidator

How to author declarative custom validation logic integrated with Hibernate Validator and Spring MVC.

import jakarta.validation.*;
import java.lang.annotation.*;

// 1. Define custom annotation
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = PhoneNumberValidator.class)
@Documented
public @interface ValidPhoneNumber {
    String message() default "Invalid phone number format. Must start with + and country code";
    Class[] groups() default {};
    Class[] payload() default {};
}

// 2. Implement ConstraintValidator
class PhoneNumberValidator implements ConstraintValidator {
    private static final String PHONE_REGEX = "^\\+[1-9]\\d{1,14}$"; // E.164 standard

    @Override
    public boolean isValid(String phone, ConstraintValidatorContext context) {
        if (phone == null || phone.isBlank()) return false;
        return phone.matches(PHONE_REGEX);
    }
}

// 3. Usage inside DTO
record UserRegistrationRequest(
    String name,
    @ValidPhoneNumber String contactNumber
) {}
Spring Boot Coding • Resilience

Program 3: In-Memory Token Bucket Rate Limiter HandlerInterceptor

Guards REST APIs against DoS and abusive scraping using a concurrent token bucket algorithm.

import jakarta.servlet.http.*;
import org.springframework.stereotype.Component;
import org.springframework.web.servlet.HandlerInterceptor;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicInteger;

@Component
public class RateLimiterInterceptor implements HandlerInterceptor {
    private static final int MAX_TOKENS = 50;
    private static final long REFILL_INTERVAL_MS = 60000; // 1 minute
    
    private final ConcurrentHashMap buckets = new ConcurrentHashMap<>();

    @Override
    public boolean preHandle(HttpServletRequest req, HttpServletResponse res, Object handler) throws Exception {
        String clientIp = req.getRemoteAddr();
        TokenBucket bucket = buckets.computeIfAbsent(clientIp, k -> new TokenBucket(MAX_TOKENS, REFILL_INTERVAL_MS));

        if (!bucket.tryConsume()) {
            res.setStatus(429); // Too Many Requests
            res.setHeader("Retry-After", "60");
            res.getWriter().write("{\"error\":\"Rate limit exceeded. Try again in 60s.\"}");
            return false;
        }
        return true;
    }

    static class TokenBucket {
        private final int capacity;
        private final long refillInterval;
        private final AtomicInteger tokens;
        private volatile long lastRefillTimestamp;

        public TokenBucket(int cap, long interval) {
            this.capacity = cap;
            this.refillInterval = interval;
            this.tokens = new AtomicInteger(cap);
            this.lastRefillTimestamp = System.currentTimeMillis();
        }

        public synchronized boolean tryConsume() {
            refill();
            if (tokens.get() > 0) {
                tokens.decrementAndGet();
                return true;
            }
            return false;
        }

        private void refill() {
            long now = System.currentTimeMillis();
            if (now - lastRefillTimestamp > refillInterval) {
                tokens.set(capacity);
                lastRefillTimestamp = now;
            }
        }
    }
}

Program 4: Dynamic Multi-Criteria Search with Spring Data JPA Specification

Avoids writing 20 static JPQL query combinations by utilizing Criteria API specifications dynamically.

import org.springframework.data.jpa.domain.Specification;
import jakarta.persistence.criteria.Predicate;
import java.util.*;

public class ProductSpecifications {
    public static Specification filterByCriteria(String name, Double minPrice, Double maxPrice, String category) {
        return (root, query, cb) -> {
            List predicates = new ArrayList<>();

            if (name != null && !name.isBlank()) {
                predicates.add(cb.like(cb.lower(root.get("name")), "%" + name.toLowerCase() + "%"));
            }
            if (minPrice != null) {
                predicates.add(cb.greaterThanOrEqualTo(root.get("price"), minPrice));
            }
            if (maxPrice != null) {
                predicates.add(cb.lessThanOrEqualTo(root.get("price"), maxPrice));
            }
            if (category != null && !category.isBlank()) {
                predicates.add(cb.equal(root.get("category"), category));
            }

            return cb.and(predicates.toArray(new Predicate[0]));
        };
    }
}

Program 5: Modern Synchronous & Resilient Client using Spring Boot 3 RestClient

Spring 6 introduced RestClient as the modern fluent alternative to legacy RestTemplate without WebFlux overhead.

import org.springframework.stereotype.Service;
import org.springframework.web.client.RestClient;
import org.springframework.http.MediaType;
import java.time.Duration;

@Service
public class OrderPaymentClient {
    private final RestClient restClient;

    public OrderPaymentClient(RestClient.Builder builder) {
        this.restClient = builder
            .baseUrl("https://payment.technointerview.com/api/v1")
            .defaultHeader("Accept", MediaType.APPLICATION_JSON_VALUE)
            .build();
    }

    public PaymentResponse processTransaction(PaymentRequest request) {
        return restClient.post()
            .uri("/charges")
            .contentType(MediaType.APPLICATION_JSON)
            .body(request)
            .retrieve()
            .onStatus(status -> status.is4xxClientError(), (req, res) -> {
                throw new PaymentClientException("Payment failed with client error: " + res.getStatusCode());
            })
            .onStatus(status -> status.is5xxServerError(), (req, res) -> {
                throw new PaymentGatewayException("Gateway unavailable, trigger circuit breaker.");
            })
            .body(PaymentResponse.class);
    }
}
