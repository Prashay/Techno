PART 2: ADVANCED & 2026 INTERVIEW SPECS

Advanced Collections, Concurrency & Memory (2026) Senior • Tech Lead • 2026

ConcurrentHashMap CAS internals, CopyOnWrite performance, Java 21 Sequenced Collections, hash-flooding DoS defenses, and modern Caffeine caching.

Concurrent Collections • Internals

1. ConcurrentHashMap Deep Dive: CAS, synchronizing on bucket head nodes, and concurrent resizing.

ConcurrentHashMap in modern Java abandons the legacy Java 7 Segment locks (which had fixed concurrency level) in favor of fine-grained bucket-level concurrency:

  • Lock-Free CAS on Empty Buckets: When inserting into an empty bucket, it uses lock-free hardware Compare-And-Swap (Unsafe / VarHandle.compareAndSetReference). If multiple threads compete to insert into the same empty slot, only one CAS succeeds; the loser retries or acquires the bucket lock.
  • Bucket-Head Synchronization: When a bucket already contains nodes (linked list or Red-Black tree), put() synchronizes only on the first node (head) of that specific bin using synchronized(firstNode). Reads (get()) remain 100% lock-free via volatile field reads.
  • Treeification Thresholds: When a single bin reaches 8 nodes and table capacity $ge 64$, the bucket is converted to a TreeBin (Red-Black tree) reducing worst-case search from $O(N)$ to $O(\log N)$.
  • Concurrent Resizing: Multiple threads assist in resizing simultaneously! When a resizing is underway, transferring threads insert special ForwardingNode markers into completed buckets so readers forward transparently to the new table.
Concurrency • Trade-offs

Java 21 Feature • JEP 431

3. Java 21 Sequenced Collections: Unifying encounter order across List, Set, and Map.

Prior to Java 21, collections with a defined encounter order lacked a common super-interface. Accessing the first or last element required inconsistent idioms (list.get(list.size() - 1) vs deque.getLast() vs set.iterator().next()). JEP 431 introduced unified interfaces:

SequencedCollection<String> seq = new ArrayList<>();
seq.addFirst("Alpha");
seq.addLast("Omega");
String first = seq.getFirst(); // "Alpha"
String last = seq.getLast();   // "Omega"

// Reverse-order view without creating expensive copies or streams!
SequencedCollection<String> reversed = seq.reversed();

This hierarchy spans SequencedCollection, SequencedSet (LinkedHashSet, SortedSet), and SequencedMap (LinkedHashMap, SortedMap) with firstEntry(), lastEntry(), and reversed().

Security • Hash Flooding DoS

4. How HashMap defends against Hash-Flooding Denial-of-Service attacks: Treeification & Hysteresis.

Hash Flooding Attack: Attackers crafted millions of malicious HTTP form parameter keys with identical hash codes. In Java 7, this collapsed HashMap into a single linked list, degrading lookup from $O(1)$ to $O(N)$ and causing 100% CPU lockup.

The Java 8+ Treeification Defense:
  • Mathematical Probability: Under a well-distributed hash function, the probability of a single bin receiving 8 collisions follows a Poisson distribution and is less than 1 in 10 million ($P(8) < 10^{-7}$).
  • Tree Conversion: If a bucket receives $ge 8$ entries, the bucket automatically transforms into a Red-Black tree (TreeNode), capping worst-case search at $O(\log N)$.
  • Hysteresis Gap: When entries are deleted, the tree reverts to a linked list only when the count drops to 6 (UNTREEIFY_THRESHOLD). This 2-node gap prevents rapid, expensive thrashing between list and tree structures during alternating add/remove operations.
High-Throughput Queues • Hardware Cache

5. ArrayBlockingQueue vs LinkedBlockingQueue: False sharing, lock contention, and memory allocation.

Choosing between blocking queues in high-throughput microservices requires understanding CPU cache lines and memory allocation:

  • ArrayBlockingQueue: Backed by a single contiguous array. Uses a single ReentrantLock shared by both producers and consumers (put and take lock each other out). However, it pre-allocates memory upfront, creating zero GC allocation churn during runtime enqueue/dequeue operations.
  • LinkedBlockingQueue: Uses two separate locks (takeLock and putLock), allowing producers and consumers to operate concurrently without blocking each other. However, every put() allocates a new Node object on the heap, generating massive Garbage Collection overhead and CPU cache-line misses under millions of operations/sec.
Caching • Modern Algorithms

6. Building high-performance In-Memory Caches: Why Caffeine Cache outperforms LinkedHashMap(accessOrder=true).

LinkedHashMap with accessOrder=true and removeEldestEntry() is the traditional textbook LRU cache. However, in concurrent production systems, it suffers from a fatal flaw:

The Mutex Bottleneck: Because LRU ordering updates the internal doubly-linked list on every cache hit, reading from the cache requires mutating the list. Wrapping it in Collections.synchronizedMap() means concurrent readers block each other completely, destroying throughput on multi-core servers.

Why Caffeine Cache Dominates in 2026:
  • Window TinyLFU (W-TinyLFU): Achieves higher hit rates than plain LRU/LFU by combining a small admission window with a frequency sketch (CountMinSketch).
  • Lock-Free Reads: Reads execute lock-free using volatile memory reads and record cache access asynchronously into thread-local ring buffers.
  • Asynchronous Maintenance: Eviction and buffer draining occur on background worker threads without stalling client request threads.
