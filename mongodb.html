PART 1: CORE & FOUNDATIONAL QUESTIONS

MongoDB Fundamentals Basic • Developer

BSON format, embedding vs referencing, and Aggregation pipeline stages.

1. MongoDB Document Model: BSON format and schema flexibility

MongoDB stores data as BSON (Binary JSON) documents inside collections. BSON supports rich data types not native to JSON (Date, ObjectId, 64-bit Int, Binary, Regex). Documents within the same collection can have flexible, evolving schemas.

2. Embedded Documents vs Normalized References

Embedding (Denormalization): Preferred when data has a 1-to-1 or bounded 1-to-few relationship and is read together (e.g., Order items inside an Order). Eliminates JOIN operations.
Referencing (Normalization): Preferred for 1-to-many unbounded relationships (e.g., User logs) or many-to-many relationships to avoid hitting the 16MB BSON document size limit.

3. Aggregation Pipeline: $match, $group, $project, and $lookup

Data flows through a multi-stage pipeline. $match filters documents early to leverage indexes, $group aggregates metrics, $project shapes fields, and $lookup performs left outer joins across collections.

PART 2: ADVANCED & 2026 INTERVIEW SPECS

Advanced MongoDB Architecture (2026) Senior • Tech Lead • 2026

Replica Set consensus, Shard key hotspotting prevention, and WiredTiger cache eviction.

High Availability • Replica Sets

1. Replica Sets, Raft Consensus, and Write Concerns (w: "majority").

MongoDB Replica Sets maintain high availability with 1 Primary and multiple Secondaries:

  • Write Concern: { w: "majority", j: true } ensures that a write is committed to the disk journal and acknowledged by a majority of replica set nodes before returning success to the client, preventing rollback on failover.
  • Read Concern: readConcern: "majority" guarantees reading data committed by a majority of nodes, preventing dirty reads of uncommitted primary writes.
Horizontal Scaling • Sharding

2. Sharding Architecture: Mongos Routers, Config Servers, and Shard Key Selection.

MongoDB scales horizontally by distributing collection chunks across Shards:

  • Shard Key Selection: Must have high cardinality, low frequency, and non-monotonically increasing values. Choosing an auto-incrementing ID or timestamp creates a hotspotting anti-pattern where all writes hit only the last shard! Use hashed shard keys or compound keys for uniform distribution.
Storage Engine • WiredTiger

3. WiredTiger Storage Engine: Cache eviction and document-level concurrency.

WiredTiger provides document-level concurrency control via lock-free algorithms and optimistic concurrency. By default, it allocates 50% of available RAM minus 1GB for its working cache, compressing data in RAM using snappy or zlib to minimize disk I/O.
